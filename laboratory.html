A verification sequence for a learned sampler

  1. Start with a tractable law. Specify the source, target, time path, and any conditioning. Derive exact moments or probabilities before fitting a model.
  2. Check the target used for regression. The conditional training target and its posterior average have different roles. The finite-risk projection identity explains why the former can train the latter.
  3. Fit a declared model class. Chapter 2 actually fits one affine function per time bin from synthetic Gaussian bridge samples. This is parameter fitting with heldout evaluation, rather than neural image training. Compare the finite fit with the best member of the chosen class and with the unrestricted oracle.
  4. Freeze the model before refining the solver. Changing model parameters and step count together confounds learning and discretization. Compare numerical integration with the exact flow when that flow can be calculated.
  5. Compare complete laws when available. Mean and variance determine the Gaussian examples here, but do not determine arbitrary non-Gaussian distributions. The finite-state chapter can compare its entire probability vector.
  6. Probe a deliberate error. Wrong Brownian scaling, an omitted score correction, a mistaken guidance interpretation, or a transposed rate matrix should fail an appropriate diagnostic. A diagnostic that cannot detect its intended error is insufficient for that purpose.

The numerical programs are small enough to inspect. Exact finite-model calculations, statistical fitting checks, and solver-refinement studies supply different evidence. None reproduces the image-model benchmarks in the cited research.

Rebuild and check the reader

From the extracted book directory, use the following commands. Rendering uses Python's standard library. The validators require the pinned packages in requirements.txt; browser checks also require an installed supported Chrome or Playwright Chromium. Reading the already-built book uses its bundled assets.

python tools/build_book.py
python tools/check_chapter_code.py
python tools/validate_book.py --browser

The execution checker copies programs into a temporary book before running them. This matters because some programs deliberately write their result files. It compares regenerated numerical results with the saved records while excluding declared creation-time and runtime fields. Scientific review of the mathematics and exercise solutions remains a separate gate.

A cumulative project

Build a sampler evaluation workbench around a distribution with a known answer. Keep the chosen law, fitted field, solver settings, random seeds, and results as separate saved records. Add conditional generation only after the unconditional case passes. Then test whether changing guidance, latent representation, or the state space preserves the particular properties you intended to preserve. The chapter counterexamples supply concrete failure cases for that workbench.
